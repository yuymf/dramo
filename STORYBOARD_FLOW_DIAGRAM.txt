TIMEOUT HIERARCHY (with cascading safety margins):

  Browser Request (60s default) ← Vercel Hobby limit
    ↓
  SSE/Long Polling (55s default) ← 5s safety margin for Vercel
    ↓
  Backend → AgentOS call (9 min = 540s) ← Generous timeout for full pipeline
    ├─ Phase 0: 90s (LLM_TIMEOUT_SECONDS)
    ├─ Phase 1: 90s per clip
    ├─ Phase 2a: 120s (ThreadPoolExecutor timeout)
    ├─ Phase 2b: 120s (ThreadPoolExecutor timeout)
    └─ Phase 3: 200s (DETAIL_REFINER_TIMEOUT_SECONDS, with 180s LLM call timeout)

═════════════════════════════════════════════════════════════════════════════════════════════════════

CONCURRENCY MODEL:

  Backend: Fire-and-forget async job
    ↓
  AgentOS Phase 1-3 Loop:
    - Outer loop: Process up to LLM_CONCURRENCY (3) clips in parallel
      - For each clip: ThreadPoolExecutor phases in sequence
        - Phase 1: Sequential (builds panel draft)
        - Phase 2a + 2b: ThreadPoolExecutor(max_workers=2) [parallel photography & acting]
        - Phase 3: Sequential (single worker, longer timeout)

  Result: ~2.5x speedup for multi-clip scripts (vs. single-threaded)

═════════════════════════════════════════════════════════════════════════════════════════════════════

ERROR RESILIENCE:

  Phase failure → Graceful degradation:
    - Phase 0 fails → 400 Bad Request
    - Phase 1 fails → Return empty panels → Phase 3 skipped → Return empty shots
    - Phase 2a/2b timeout → Use empty array, continue to Phase 3
    - Phase 3 timeout → Use raw panels as fallback
    - JSON parse error → 502 Bad Gateway (retryable)

  No cascade failures: Later phases never crash if earlier phases degrade.
